025纹理流送：开放世界怎么加载 4K 贴图

《原神》一个区域的贴图加起来几个 GB，手机内存只有 6-8GB——不可能全加载。答案：纹理流送（Texture Streaming）——只加载当前需要的，用完就扔。

核心概念

纹理流送 Texture Streaming

按需加载贴图：相机靠近时加载高清版，远离时卸载。不是一次性全加载，而是"流式"进出内存。核心挑战：怎么判断"需要什么"，怎么无缝切换。

Mipmap 多级渐远纹理

同一张贴图的多个分辨率版本：4096×4096 → 2048 → 1024 → ... → 1×1。远处用低分辨率（省显存+减少闪烁），近处用高分辨率。GPU 自动按距离选级别。

纹理压缩 Texture Compression

ASTC/ETC2/BC 等格式，把贴图压缩到 1/4~1/8 大小，GPU 直接解压渲染。手机必备——不压缩的 4K 贴图一张就 64MB，压缩后 8-16MB。

Mipmap：纹理流送的基础

// Mipmap 层级
4096×4096 (原始)  ← 近处用
2048×2048 (1/4)   ← 中距离
1024×1024 (1/16)  ← 远处
512×512   (1/64)  ← 很远
...
1×1       (平均色) ← 极远

// 内存增加：原始 × 1.33（每级是上一级的 1/4，等比数列求和）

纹理流送策略

策略原理适合
距离流送相机距离决定加载哪个 mip 级别通用，最常用
区域流送世界分块，进入区域加载该区域的贴图开放世界
可见性流送只加载可见物体的贴图室内/线性关卡
预测流送根据移动方向预测即将需要的贴图高速移动场景
// 距离流送的简化逻辑
func update_streaming():
    var camera_pos = camera.global_position
    for texture in textures:
        var dist = camera_pos.distance_to(texture.world_position)
        var required_mip = calculate_mip_from_distance(dist)
        
        if required_mip < texture.loaded_mip:
            load_higher_mip(texture, required_mip)  # 靠近，加载高清
        elif required_mip > texture.loaded_mip + 1:
            unload_to_mip(texture, required_mip)    # 远离，卸载高清

流送的挑战

挑战原因解决
突然模糊高清贴图还没加载完预测加载+渐隐过渡
卡顿加载大贴图时 IO 阻塞异步加载+分帧加载
内存抖动频繁加载卸载LRU 缓存+滞回区间
磁盘空间所有 mip 级别都存只存需要的级别+压缩
纹理 pop-in 是开放世界的通病：走近一个建筑，贴图从模糊突然变清晰——这就是流送没跟上。解决：提前加载（预测玩家移动方向）+ 渐隐过渡（不要瞬间切换）。

口头描述练习

🗣️ 开放世界手游的纹理流送方案怎么描述？

"纹理压缩：ASTC 6×6（8:1 压缩），角色贴图 ASTC 4×4（质量优先），地形贴图 ASTC 8×8（压缩优先）。Mipmap：全部开，远处自动降级。流送策略：距离+区域混合——世界分 500m×500m 块，进入块加载该区域贴图，块内按距离控制 mip 级别。预测加载：根据玩家移动方向，提前加载前方 2 个块的贴图。渐隐过渡：贴图切换用 0.3 秒 crossfade，避免 pop-in。LRU 缓存：最近使用的 200 张贴图保留在内存，超出后卸载最久没用的。异步加载：所有贴图加载在后台线程，主线程不阻塞。内存预算：贴图总内存控制在 1.5GB 以内（手机 6GB 内存，系统占 2GB，游戏逻辑占 1.5GB）。"

→ 你用了 ASTC 分级压缩、距离+区域混合流送、预测加载、渐隐过渡、LRU 缓存、异步加载、内存预算。这就是完整的开放世界纹理流送方案。
