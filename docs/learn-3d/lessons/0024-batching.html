024批处理与实例化：一万棵草怎么画

场景里有一万棵草、五千块石头、两千棵树——如果每个都单独画，CPU 要发一万次命令，GPU 切换一万次状态，帧率直接掉到个位数。解决方案：把"画很多次"变成"画一次"。

核心概念

Draw Call 绘制调用

CPU 告诉 GPU"画这个物体"的一次命令。每次 Draw Call 都有固定开销——设置状态、绑定纹理、传参数。Draw Call 太多，CPU 就忙不过来了，GPU 在等命令，帧率下降。

批处理 Batching

把多个物体合并成一次 Draw Call。静态批处理：合并不动的物体；动态批处理：合并小物体；GPU 实例化：同一个 mesh 画很多次。

GPU 实例化 GPU Instancing

同一个 mesh 用不同的变换（位置/旋转/缩放）画 N 次，只发一次 Draw Call。变换数据存在 GPU 显存里，shader 里用 gl_InstanceID 索引。草、树、石头、子弹——同 mesh 大量重复物体的救星。

GPU 实例化：草的救星

// 传统方式：一万棵草 = 一万次 Draw Call
for (int i = 0; i < 10000; i++) {
  setTransform(grassTransform[i]);
  draw(grassMesh);  // ← 一万次 Draw Call
}

// GPU 实例化：一万棵草 = 一次 Draw Call
setTransforms(grassTransforms);  // 所有变换一次性传给 GPU
drawInstanced(grassMesh, 10000);  // ← 一次 Draw Call
// shader 里用 gl_InstanceID 索引变换
// vertex shader
layout(location = 0) in vec3 position;
layout(location = 1) in vec3 instanceOffset;  // 每实例数据

void main() {
  vec3 worldPos = position + instanceOffset;
  gl_Position = projection * view * vec4(worldPos, 1.0);
}

Three.js 实现

// InstancedMesh：Three.js 的 GPU 实例化
const grassGeometry = new THREE.PlaneGeometry(0.5, 1);
const grassMaterial = new THREE.MeshStandardMaterial({ color: 0x3a5f3a });
const count = 10000;

const instancedMesh = new THREE.InstancedMesh(grassGeometry, grassMaterial, count);

// 设置每个实例的变换
const matrix = new THREE.Matrix4();
for (let i = 0; i < count; i++) {
  matrix.setPosition(
    Math.random() * 100 - 50,
    0,
    Math.random() * 100 - 50
  );
  instancedMesh.setMatrixAt(i, matrix);
}
instancedMesh.instanceMatrix.needsUpdate = true;

scene.add(instancedMesh);  // 一次 Draw Call 画一万棵草

Godot 实现

# Godot 4：MultiMeshInstance3D
extends Node3D

func _ready():
    var multi_mesh = MultiMesh.new()
    multi_mesh.transform_format = MultiMesh.TRANSFORM_3D
    multi_mesh.mesh = preload("res://grass.mesh")
    multi_mesh.instance_count = 10000
    
    # 设置每个实例的变换
    for i in 10000:
        var transform = Transform3D()
        transform.origin = Vector3(
            randf_range(-50, 50), 0, randf_range(-50, 50)
        )
        multi_mesh.set_instance_transform(i, transform)
    
    var instance = MultiMeshInstance3D.new()
    instance.multimesh = multi_mesh
    add_child(instance)  # 一次 Draw Call

问题原因解决

合批失败顶点属性不同统一顶点格式
合批失败物体在动静态批处理只合不动的
实例化失败mesh 不同只有同 mesh 能实例化
阴影穿帮实例化阴影单独算开实例化阴影支持
合批不是万能的：合批减少 Draw Call，但合并后的 mesh 可能很大（内存增加），而且不能单独控制每个物体（要动就得拆开）。合批是"用内存换 CPU 时间"的权衡。

🗣️ 开放世界手游的植被方案怎么描述？

"草：GPU 实例化（MultiMeshInstance3D），同 mesh 不同变换，一次 Draw Call 画几万棵。配合顶点动画摇摆（022 学过的正弦公式），LOD 远处用 billboard。树：近景高模用 GPU 实例化（同树种同 mesh），中景 LOD，远景 billboard 贴图。石头/灌木：同树，实例化为主。建筑：静态批处理——不动的建筑合并成大 mesh，减少 Draw Call。小道具（箱子/罐子）：动态批处理，小 mesh 自动合批。Draw Call 预算 200 以内，植被占 30%（实例化后 Draw Call 很少），建筑 40%，角色 20%，特效 10%。"
