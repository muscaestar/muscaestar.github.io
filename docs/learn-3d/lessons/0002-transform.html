002变换：位置、旋转、缩放

第 1 课讲了场景图——节点怎么组织。这节课讲每个节点身上的三个属性：它在哪里、朝哪边、有多大。

核心概念

位置 Position / Translation

节点在 3D 空间中的坐标，用 (x, y, z) 表示。Three.js 里是 position，Godot 里也是 position。

旋转 Rotation

节点的朝向，绕 x/y/z 三个轴的旋转角度。Three.js 用弧度（radians），Godot 默认也用弧度但编辑器里显示角度（degrees）。

缩放 Scale

节点的大小倍数，(1, 1, 1) 是原始大小，(2, 2, 2) 放大一倍，(0.5, 0.5, 0.5) 缩小一半。三个轴可以不同（非均匀缩放）。

局部坐标 Local Space

相对于父节点的坐标。你在旋转地球 demo 里写的 earthGroup.rotation.z = -23.4° 就是局部旋转——它影响 Group 内所有子节点。

世界坐标 World Space

相对于场景原点的绝对坐标。最终显示位置 = 从根到当前节点所有局部变换的叠加。

坐标系：哪个轴朝哪？

Three.js 和 Godot 都用右手坐标系：

轴方向类比
X右（正）/ 左（负）左右移动
Y上（正）/ 下（负）上下移动
Z朝观察者（正）/ 远离（负）前后移动
记忆法：伸出右手，拇指=X（右）、食指=Y（上）、中指=Z（朝向自己）。这就是"右手坐标系"的由来。

你已经用过的变换

旋转地球 demo 里到处都是变换：

// 位置：把相机放到 (0, 0, 3.8)
camera.position.set(0, 0, 3.8);

// 旋转：地轴倾斜 -23.4°（转弧度）
earthGroup.rotation.z = THREE.MathUtils.degToRad(-23.4);

// 旋转：自转动画，每帧绕 Y 轴转一点
earthGroup.rotation.y += dt * speed;

// 缩放：云层球体比地球略大
new THREE.SphereGeometry(1.012, 64, 64)  // 通过几何体大小
// 等价于
clouds.scale.set(1.012, 1.012, 1.012)   // 通过缩放

弧度 vs 角度

这是个容易踩的坑：

// Three.js — 必须用弧度
mesh.rotation.x = Math.PI / 2;        // 90°
mesh.rotation.x = Math.PI;            // 180°
mesh.rotation.x = Math.PI * 2;        // 360°

// 换算
const deg = 90;
const rad = deg * Math.PI / 180;      // 角度 → 弧度
const rad2 = THREE.MathUtils.degToRad(deg); // 用工具函数

// Godot — 代码里也是弧度，但编辑器显示角度
node.rotation.x = deg_to_rad(90)
常见错误：写 rotation.x = 90 以为是 90°，实际是 90 弧度 ≈ 5157°。物体疯狂旋转。始终记得用 degToRad() 转换。

局部 vs 世界：一个例子

场景
└── carGroup (position: 10, 0, 0)   ← 世界坐标 (10, 0, 0)
    └── wheel (position: 1, 0.5, 0) ← 局部坐标 (1, 0.5, 0)
                                      世界坐标 = (11, 0.5, 0)

轮子的 position 是 (1, 0.5, 0)——这是相对于车身的位置。车移动到 (20, 0, 0)，轮子的世界坐标自动变成 (21, 0.5, 0)，不需要手动更新。

这就是第 1 课说的"子节点继承父节点变换"的具体含义。

口头描述练习

🗣️ 做一个旋转木马场景，怎么描述？

"场景中心有一个 Group 作为旋转木马的底座，position 在原点 (0, 0, 0)。底座上面有四匹马，每匹马是一个 Group，position 分别在 (2, 0, 0)、(0, 0, 2)、(-2, 0, 0)、(0, 0, -2)——相对于底座的局部坐标。每匹马有一个上下浮动的动画（position.y 在 0 到 0.5 之间循环）。底座 Group 绕 Y 轴匀速旋转（rotation.y 每帧增加），四匹马作为子节点跟着一起转。"

→ 你用 position + rotation + Group 层级关系完整描述了一个旋转木马。这就是将来指挥 agent 的方式。
