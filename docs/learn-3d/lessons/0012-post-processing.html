012后处理：画面最后的润色

场景渲染完了，但画面还差点"味道"——灯光没有辉光，暗部死黑，整体发灰。这时候上后处理：不动场景，直接对渲染好的画面做滤镜。就像拍照后的修图。

核心概念

后处理 Post-processing

场景渲染成一张图片后，对这张图片做的所有处理。不碰几何体和材质，直接操作像素——像 Photoshop 滤镜，但是每帧实时执行。

渲染目标 Render Target

后处理的前提：场景不直接画到屏幕，而是画到一张纹理（Render Target）。然后对这张纹理做处理，最后才显示。

通道 Pass

每个后处理效果是一个 pass。多个效果串成链：渲染场景 → Bloom → 色调映射 → 暗角 → 屏幕。每个 pass 读上一个的结果。

后处理的工作原理

传统渲染：
  场景 → 直接画到屏幕

后处理渲染：
  场景 → 画到纹理 A（Render Target）
         ↓
  纹理 A → Bloom pass → 纹理 B
         ↓
  纹理 B → 色调映射 pass → 纹理 C
         ↓
  纹理 C → 暗角 pass → 屏幕

每个 pass 就是一次全屏 shader：
  输入一张纹理，逐像素处理，输出新纹理
类比：后处理链 = Photoshop 的图层滤镜。原图（场景渲染）→ 辉光滤镜（Bloom）→ 曲线调整（色调映射）→ 暗角滤镜（Vignette）→ 导出（屏幕）。区别是游戏每秒做 60 次。

常见后处理效果

辉光 Bloom
亮部向外溢出光晕。原理：提取画面中超过亮度阈值的像素 → 高斯模糊 → 叠加回原图。
→ 霓虹灯、太阳、魔法、科幻 UI 的发光感
成本：中等（需要多次模糊 pass）
色调映射 Tone Mapping
把 HDR（高动态范围）颜色压缩到屏幕能显示的 LDR 范围。不是简单截断，而是用曲线压缩——亮部不过曝，暗部有细节。
→ 所有 HDR 渲染的必经之路，决定画面的"电影感"
成本：便宜（每像素一次计算）
暗角 Vignette
画面四角变暗，视线聚焦中心。
→ 恐怖游戏氛围、照片感、引导视线
成本：极便宜
色差 Chromatic Aberration
RGB 三通道轻微错位，边缘出现红蓝重影。模拟相机镜头的色散缺陷。
→ 受击特效、失真/迷幻场景、复古镜头感
成本：便宜
景深 Depth of Field, DOF
焦点清晰，前景/背景模糊。模拟相机光圈。
→ 对话特写、引导注意力、电影感
成本：贵（需要深度图 + 多次模糊）
运动模糊 Motion Blur
快速移动的物体拖出残影。模拟相机快门。
→ 高速赛车、动作游戏、掩盖低帧率
成本：中等到贵（需要速度缓冲）
屏幕空间环境光遮蔽 SSAO
根据深度图计算缝隙/角落的遮蔽，实时加深凹陷处。是 AO 贴图的实时版。
→ 增加场景立体感和接触阴影
成本：贵（需要深度+法线缓冲，大量采样）
颜色分级 Color Grading / LUT
整体调色：对比度、饱和度、色温、色调分离。常用 LUT（查找表）——把调色结果存成一张小纹理，实时映射。
→ 统一画面风格（赛博朋克蓝橙、末日黄褐）
成本：便宜

HDR 与色调映射

为什么需要色调映射？因为真实世界的亮度范围远超屏幕：

真实世界亮度（HDR）：
  星光 0.001 → 室内 100 → 阳光 100,000

屏幕显示范围（LDR）：
  0 → 1（255 级）

直接截断：阳光和台灯都显示成 1.0（纯白）→ 过曝
色调映射：用曲线压缩 → 都亮但能区分

常用曲线：
  Reinhard:   c / (1 + c)        简单，亮部压缩明显
  ACES:       电影工业标准        保留色彩，电影感
  Uncharted2: 游戏常用            暗部细节好
ACES 是现在的默认选择——好莱坞电影工业标准，Three.js 和 Godot 都内置。换色调映射曲线是改变画面"电影感"最快的方法。

Three.js 实现

// EffectComposer：后处理链管理器
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { UnrealBloomPass } from 'three/addons/postprocessing/UnrealBloomPass.js';

// 1. 创建 composer
const composer = new EffectComposer(renderer);

// 2. 第一个 pass 必须是 RenderPass（渲染场景到纹理）
composer.addPass(new RenderPass(scene, camera));

// 3. 添加效果 pass
const bloom = new UnrealBloomPass(
  new THREE.Vector2(window.innerWidth, window.innerHeight),
  0.5,   // 强度
  0.4,   // 半径
  0.85   // 阈值（多亮才发光）
);
composer.addPass(bloom);

// 4. 渲染循环改用 composer
function animate() {
  composer.render();  // 替代 renderer.render()
}

// 色调映射不用 pass，直接在 renderer 上设：
renderer.toneMapping = THREE.ACESFilmicToneMapping;
renderer.toneMappingExposure = 1.0;

Godot 实现

# Godot 4：WorldEnvironment 节点 + Environment 资源
# 大部分后处理是内置开关，不用写代码

# Environment 资源里的选项：
glow_enabled = true              # 辉光（Bloom）
glow_intensity = 0.5
glow_bloom = 0.3                 # 阈值

tonemap_mode = Environment.TONE_MAPPER_ACES

adjustment_enabled = true        # 颜色分级
adjustment_brightness = 1.0
adjustment_contrast = 1.1
adjustment_saturation = 1.05

ssao_enabled = true              # SSAO
volumetric_fog_enabled = true    # 体积雾（第 20 课）
Godot 的优势：后处理全部内置在 Environment 资源里——辉光、SSAO、色调映射、雾、调整，打勾就有。Three.js 要自己拼 EffectComposer 链。这就是为什么 Godot 适合快速出效果。

手机端的取舍

效果手机建议替代方案
Bloom✅ 可用（低分辨率模糊）自发光贴图假装发光
色调映射✅ 必用（几乎免费）—
暗角✅ 可用（免费）—
颜色分级✅ 可用（LUT 很便宜）—
SSAO⚠️ 慎用（贵）烘焙 AO 贴图
景深⚠️ 慎用（贵）只在过场动画用
运动模糊❌ 一般不用提高帧率更重要

口头描述练习

🗣️ 做一个夜晚赛博朋克场景，怎么描述后处理需求？

"后处理链：先 Bloom——阈值调低（0.7）让霓虹灯和招牌都发光，强度中等别糊成一片。然后 ACES 色调映射，曝光 1.2 提亮夜景。颜色分级用 LUT 做蓝橙色调——阴影偏蓝，高光偏橙。再加轻微色差（屏幕边缘 RGB 错位）增加镜头感。最后暗角 0.3 聚焦视线。手机端：SSAO 关掉，用烘焙 AO 贴图替代。"

→ 你用了 Bloom 阈值/强度、ACES、曝光、LUT 色调分离、色差、暗角、性能取舍。这就是完整的后处理方案描述。
