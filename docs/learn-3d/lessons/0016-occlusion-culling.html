016遮挡剔除：看不见的就不渲染

上节课的 LOD 让远处的东西变便宜，这节课更狠：看不见的东西直接不渲染。你站在走廊里，墙后面的 100 个房间——GPU 根本不该知道它们存在。

核心概念

剔除 Culling

渲染之前先做一轮筛选：这个物体有可能被看到吗？不可能就不提交给 GPU。剔除发生在 CPU 侧，省的是 GPU 的渲染开销。

视锥剔除 Frustum Culling

相机视野是一个锥体（视锥），锥体外的物体不渲染。你背后的敌人、头顶的鸟——自动跳过。引擎默认开启，不用配置。

遮挡剔除 Occlusion Culling

物体在视锥内，但被其他物体挡住了（墙后面的房间）——也不渲染。这是本课重点，比视锥剔除难得多。

三层剔除体系

第一层：视锥剔除 Frustum Culling
物体的包围盒和相机视锥求交，不相交就跳过。数学简单（几次点积），每个引擎默认做。
成本：极便宜 | 效果：屏幕外的物体不渲染
第二层：距离剔除 Distance Culling
超过 visibility_range 的物体直接跳过。LOD 的最后一级——再远就彻底消失。
成本：极便宜 | 效果：远处物体不渲染
第三层：遮挡剔除 Occlusion Culling
物体在视锥内、距离内，但被墙挡住了。判断"被挡住"比判断"在锥内"难得多——需要知道场景的空间结构。
成本：中等到贵 | 效果：被挡住的物体不渲染（室内大杀器）

遮挡剔除的三种实现

方案原理适用成本
PVS（潜在可见集）预处理：把场景分区，离线算出"站在 A 区能看到哪些区"，存成表。运行时查表。静态室内（房间、走廊）运行时极便宜，预处理耗时
遮挡查询（GPU）渲染时问 GPU："这个包围盒画出来会有像素可见吗？"没有就跳过。有延迟（上一帧的结果）。动态场景、城市中等（查询开销+延迟容忍）
软件光栅化CPU 把大型遮挡物（建筑）画成低分辨率深度图，逐个测试物体是否被挡。大场景、主机/PC较贵（但比渲染物体便宜）
手游主流：PVS 思路的变体。静态场景预处理可见性，动态物体（角色）单独处理。Godot 的 OccluderInstance3D 就是半自动方案——标记哪些物体是"遮挡物"，引擎烘焙数据。

房间-门户系统（经典案例）

室内游戏最经典的遮挡方案，思想极其简单：

场景组织：
  房间 A ←门→ 走廊 ←门→ 房间 B

规则：
  玩家在房间 A
  → 渲染房间 A + 走廊（通过门能看见）
  → 房间 B 不渲染（门关着/门后还有拐角）

实现：
  每个区域存一个"门户列表"（门、窗）
  渲染时：当前区域 + 通过可见门户连通的区域
  门户本身可以做视锥测试（门在视野里才展开）
这个思想影响深远：《半条命》《使命召唤》的室内关卡都是房间-门户结构。做室内游戏时，关卡设计（怎么摆墙和门）本身就是一种性能优化——转角多 = 天然遮挡多 = 渲染负担小。

剔除的边界情况

情况问题处理
物体很大，包围盒跨多个区域任何区域都"可能看到一点"拆分物体，或接受不剔除
阴影投到可见区域物体看不见但影子看得见阴影剔除用更大的范围
反射里能看到镜子/水面反射出被剔除的物体反射探针独立渲染，不剔除
剔除导致"闪现"快速转身时物体突然弹出剔除范围留余量（比视锥大 10%）

剔除 vs LOD 的分工

一个物体的生命周期（从远到近）：

  极远 → 距离剔除（不存在）
    ↓
  很远 → Billboard（2 个三角形）
    ↓
  远   → LOD3（剪影）
    ↓
  被墙挡 → 遮挡剔除（不存在）  ← 本课
    ↓
  中   → LOD1/LOD2
    ↓
  屏幕外 → 视锥剔除（不存在）  ← 引擎自动
    ↓
  近   → LOD0（全细节）

LOD 让物体"变便宜"，剔除让物体"不存在"。
先剔除（不存在的不用再分级），再 LOD（存在的选精度）。

Godot 实现

# Godot 4：OccluderInstance3D 节点
# 1. 在墙、建筑等大型静态物体下放 OccluderInstance3D
# 2. 选择 occluder 形状（盒子/多边形）
# 3. 烘焙：Project 菜单 → Bake Occluders

# 被遮挡的物体设置：
# MeshInstance3D → Occlusion Culling →
#   occluder_culling_mode = OCCLUDER_CULLING_BAKED

# 视锥剔除：默认开启，不用管
# 距离剔除：visibility_range_end（上节课讲过）

口头描述练习

🗣️ 城市开放世界的剔除方案怎么描述？

"三层剔除组合：视锥剔除引擎自带不用管；距离剔除分类型——小物件 200m，建筑 2km，地形 5km+imposter；遮挡剔除用建筑做 occluder——每栋楼挂 OccluderInstance3D，烘焙时标记为遮挡物，街道级的小物件设为可遮挡。室内单独做房间-门户系统。反射和阴影的剔除范围比本体大 15%，防止转身时闪现。动态物体（车辆、行人）不参与烘焙，用运行时 GPU 遮挡查询。"

→ 你用了三层剔除、分类距离、occluder 标记、房间-门户、剔除余量、动静分离。这就是完整的城市场景剔除方案。
