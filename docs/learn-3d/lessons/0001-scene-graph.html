001场景图：3D 世界的骨架

你在旋转地球 demo 中已经写过 scene.add(earth)、earthGroup.add(clouds)。这节课讲清楚：为什么是这样组织的？

核心概念

场景 Scene

3D 世界的容器。所有可见的物体、光照、相机都生活在场景里。想象一个摄影棚：场景就是那个棚子。

场景图 Scene Graph

场景内部的组织方式——一棵树状结构。每个物体（节点）可以有子节点，子节点跟随父节点移动、旋转、缩放。就像人体：手是手臂的子节点，手臂一动，手跟着动。

节点 Node / Object3D

场景图中的每一个成员。Three.js 里叫 Object3D，Godot 里叫 Node3D。Mesh、Light、Camera、Group 都是节点。

层级关系 Hierarchy / Parent-Child

节点之间的父子关系。子节点继承父节点的变换——父节点移动，所有子孙跟着动。这是组织复杂场景的核心机制。

你已经用过的场景图

回顾旋转地球的代码结构：

Scene
├── Points (星空)
├── AmbientLight
├── DirectionalLight (主光)
├── DirectionalLight (补光)
├── earthGroup (Group)
│   ├── earth (Mesh — 地球本体)
│   └── clouds (Mesh — 云层)
└── glow (Mesh — 大气辉光)

注意 earthGroup：地球和云层是它的子节点。当你写 earthGroup.rotation.y += dt * speed 时，地球和云层一起转——这就是层级继承。

Godot 对照：Godot 的场景树（Scene Tree）和 Three.js 的场景图是同一个概念。Godot 的 Node3D 对应 Three.js 的 Object3D，Node3D.add_child() 对应 object.add()。

为什么需要 Group？

Group 是一个"空"节点——它本身不可见，但可以把多个物体组织在一起。在地球 demo 里：

// 不用 Group：要分别旋转两个物体
earth.rotation.y += dt * speed;
clouds.rotation.y += dt * speed * 0.35;

// 用 Group：转父节点就行，子节点自动跟随
earthGroup.rotation.y += dt * speed;
clouds.rotation.y += dt * speed * 0.35; // 额外独立漂移

云层在 Group 内还有自己的旋转（比地球慢一点），这就是局部变换叠加在父级变换之上的效果。

口头描述练习

试着用今天学的术语描述这个场景（先自己想，再展开对照）：

🗣️ 我想做一个太阳系模型，怎么说？

"场景里有一个 Group 作为太阳系的中心，太阳 Mesh 是它的子节点。地球 Group 也是它的子节点，地球 Mesh 和月球 Mesh 是地球 Group 的子节点。太阳 Group 自转带动所有行星公转，地球 Group 自转带动月球绕地球转。"

→ 你刚才用场景图描述了一个完整的层级结构，这就是将来指挥 agent 的方式。
