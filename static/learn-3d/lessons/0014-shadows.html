014阴影进阶：级联、软阴影、常见坑

入门课里你已经会开阴影了：`castShadow = true` 就完事。但真做项目时问题就来了——远处阴影糊成一片、物体表面出现条纹、阴影边缘闪烁。这节课讲阴影的实现原理，以及三大进阶问题怎么解决。

核心概念

阴影贴图 Shadow Map

阴影的实现方式：从光源视角渲染一张"深度图"（记录每个像素离光多远）。渲染物体时，把像素位置转换到光源视角，比较深度——比深度图远 = 被挡住 = 在阴影里。

阴影相机 Shadow Camera

光源的"视角范围"。方向光的阴影相机是一个盒子（frustum），只有盒子里的物体才有阴影。盒子外的世界——没有阴影。

级联阴影贴图 Cascaded Shadow Maps (CSM)

把视锥切成几段，每段用一张独立的高精度阴影贴图。近处用细精度贴图（清晰），远处用粗精度（反正看不清）。解决大场景阴影模糊的标准方案。

阴影贴图原理

第一步：从光源渲染深度图
  光源视角看到的场景 → 记录每个像素的深度
  （这张图上没有颜色，只有"离光多远"）

第二步：渲染主相机画面
  对每个像素：
    1. 算出它在光源视角下的深度 d1
    2. 查阴影贴图同位置的深度 d2
    3. d1 > d2 → 被挡住了 → 阴影
       d1 ≈ d2 → 光直接照到 → 亮
直觉：阴影贴图就是"光看到了什么"。光看到的地方亮，光看不到的地方（被挡住了）就是阴影。所以阴影质量完全取决于这张深度图的分辨率和覆盖范围。

问题 1：阴影模糊（分辨率不足）

阴影贴图本质是纹理——一张 1024×1024 的图要覆盖整个阴影相机范围。范围越大，每个像素覆盖的实际面积越大，阴影越糊。

阴影相机范围1024 贴图精度效果
10 米~1cm/像素清晰锐利
100 米~10cm/像素边缘锯齿明显
1000 米~1m/像素糊成一片
// Three.js：提高分辨率 + 收紧范围
light.shadow.mapSize.set(2048, 2048);  // 更大贴图（更贵）
light.shadow.camera.left = -20;        // 收紧相机范围
light.shadow.camera.right = 20;        // 只覆盖需要的区域
light.shadow.camera.top = 20;
light.shadow.camera.bottom = -20;

解决：级联阴影（CSM）

视锥切 3 段，每段一张 1024 阴影贴图：

  近处（0~30m）   → 贴图 1：10cm/像素，清晰
  中距（30~100m） → 贴图 2：30cm/像素，够用
  远处（100~500m）→ 贴图 3：1.5m/像素，反正看不清

总开销：3 张 1024 贴图 ≈ 1 张 2048 的开销
但近处精度 = 2048 贴图覆盖 30m 的精度
Godot 直接内置：DirectionalLight3D → Shadow → 开启 PSSM（Parallel Split Shadow Maps），设置 2~4 级 split。Three.js 需要 CSM 插件（three/examples/jsm/csm/CSM.js）。

问题 2：阴影失真（Shadow Acne / Peter-Panning）

两个经典的阴影 bug，根源都是深度精度：

Bug现象原因解决
Shadow Acne物体表面出现条纹/噪点状阴影深度图精度有限，表面自己和自己比较时误判"被挡住"加 bias（偏移）：比较时把深度往外推一点
Peter-Panning阴影和物体分离，像物体悬浮bias 加太大，"被推出去"的深度超过了实际缝隙调小 bias，或用 normal bias
// Three.js：bias 调参
light.shadow.bias = -0.0001;         // 消除 acne
light.shadow.normalBias = 0.02;      // 沿法线偏移，对斜面更好

// 调试方法：bias 从 0 开始，慢慢加直到 acne 消失
// 加过头了出现 Peter-Panning → 往回调
bias 没有万能值——和场景尺度、相机范围都相关。大场景（公里级）需要更大的 bias。这就是为什么引擎里都暴露这个参数让你调。

问题 3：硬阴影 vs 软阴影

真实世界的阴影边缘不是锐利的——光源有面积，半影区（penumbra）是渐变：

类型原理效果成本
硬阴影深度比较，非黑即白边缘锐利，风格化最便宜
PCF采样周围几个像素取平均边缘柔和，通用便宜
PCSS半影宽度随遮挡物距离变化近实远虚，真实中等
VSM存深度的平方，用统计估计软但可能漏光中等
// Three.js：切换阴影类型
renderer.shadowMap.type = THREE.BasicShadowMap;     // 硬阴影
renderer.shadowMap.type = THREE.PCFShadowMap;       // PCF（默认）
renderer.shadowMap.type = THREE.PCFSoftShadowMap;   // PCF 软
renderer.shadowMap.type = THREE.VSMShadowMap;       // VSM

// Godot：DirectionalLight3D → Shadow → Blur 调模糊度
PCSS 的直觉：用手挡太阳——手贴近地面时影子锐利，手举高时影子模糊。遮挡物离接收面越远，半影越大。这是最真实的软阴影算法，但手机上一般用 PCF 就够了。

手机端阴影策略

策略做法适用
烘焙阴影静物阴影烘到 lightmap，实时阴影只给角色大多数手游
单级联 + 紧范围阴影相机只覆盖玩家周围 30 米，跟着主角走第三人称游戏
低分辨率 + PCF1024 贴图 + PCF 软阴影，锯齿被模糊掩盖性能紧张时
假阴影角色脚下贴一个圆形渐变贴图（blob shadow）超休闲游戏

🗣️ 开放世界手游的阴影方案怎么描述？

"方向光用 3 级 CSM：近处 30m 高精度（角色和近景清晰），中距 100m 中等，远处 500m 粗精度（反正看不清）。每级 1024 贴图，PCF 软阴影。bias 按场景尺度调到 0.0005，normalBias 0.05。建筑和地形阴影烘焙到 lightmap，实时阴影只管角色和动态物体。性能模式下降为 2 级 CSM + 512 贴图。远处的树用 blob shadow 贴片。"

→ 你用了 CSM 分级策略、贴图预算、bias 调参、烘焙+实时混合、降级方案、blob shadow。这就是完整的阴影方案描述。
