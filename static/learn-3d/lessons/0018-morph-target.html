018网格变形：表情、嘴唇和顶点动画

第 8 课学过骨骼动画——骨骼带动皮肤。但角色说话时嘴唇的蠕动、眨眼时眼皮的褶皱，用骨骼做又笨又假。这类精细的局部变形有专门的技术：Morph Target。

核心概念

Morph Target 形态目标 / 混合形状（Blend Shape）

同一个网格做多个"版本"——基础脸、微笑脸、眨眼脸。每个版本只是顶点位置不同（顶点数、拓扑完全一样）。运行时按权重混合：30% 微笑 + 100% 眨眼，顶点位置线性插值。

顶点动画 Vertex Animation

更广义的概念：直接在顶点级别做动画，不走骨骼。Morph target 是"离散版本间插值"，顶点动画也可以是"每帧用公式算"（水面波动、旗帜飘动）。

骨骼 vs Morph Target：分工

骨骼动画Morph Target
原理骨骼变换带动顶点预存多个顶点版本，按权重插值
适合大范围刚体运动（走路、挥手）精细局部变形（表情、嘴唇）
精度关节处容易失真美术逐顶点雕刻，完全可控
内存便宜（只存骨骼）贵（每个 target 存一份顶点）
典型部位四肢、脊柱、颈部脸、手指细节、肌肉膨胀
行业惯例：脸用 morph，身体用骨骼。一个 AAA 角色通常有 50~100 个脸部 morph target（各种表情、26 个英文字母的口型、viseme 音素口型），身体还是骨骼驱动。两者同时作用，互不干扰。

Morph Target 原理

基础网格（neutral face）：顶点 P = (x, y, z)
Morph target A（smile）：   顶点 P' = P + ΔA
Morph target B（blink）：    顶点 P'' = P + ΔB

存储：只存偏移量 Δ（比存完整顶点省空间）

运行时混合：
  final = P + w1×ΔA + w2×ΔB + w3×ΔC + ...
  
  例子：w_smile=0.7, w_blink=1.0
  → 70% 微笑 + 100% 眨眼 = 笑着闭眼

权重通常是 0~1，但可以 >1（夸张化）或 <0（反表情）

为什么可以叠加

因为每个 target 只动一小片区域的顶点：微笑动嘴角，眨眼动眼皮。嘴角的 ΔA 和眼皮的 ΔB 不冲突，直接相加。这就是表情系统的数学基础——线性叠加近似。

叠加的边界：两个 target 动同一片顶点时会打架（比如"大笑"和"嘟嘴"都动嘴）。解决：美术做"组合 target"（大笑+嘟嘴的专用修正版），引擎检测到组合时自动叠加修正。这叫 corrective blend shape。

实际应用

场景做法
口型同步（Lip Sync）音频分析 → 音素序列（a/e/i/o/u）→ 对应 viseme target 权重随时间变化
表情系统情绪状态机 → 多个 target 权重组合（开心 = 微笑 80% + 眯眼 40%）
肌肉膨胀弯曲手臂时，肱二头肌 target 权重跟肘关节角度联动
伤害变形中弹部位凹陷 target，权重 = 伤害程度
角色定制捏脸系统：鼻子高低、眼睛大小都是 morph target 滑块

顶点动画（公式驱动）

Morph target 是"预存版本插值"，还有一类是"每帧现算"——适合规则运动：

// 旗帜飘动：顶点 shader 里用正弦波
// x 越小（旗杆侧）越不动，x 越大（自由端）摆越大
pos.z += sin(pos.x * 2.0 + time * 5.0) * pos.x * 0.1;

// 水面波动：多个正弦波叠加（就是廉价的 fBm）
pos.y += sin(pos.x * 0.5 + time) * 0.3
       + sin(pos.z * 0.8 + time * 1.3) * 0.2;

// 草地摇摆：顶点越高摆越大
pos.x += sin(time * 2.0 + worldPos.x) * pos.y * 0.05;
顶点动画在 GPU 上跑（顶点 shader），CPU 完全不参与——一万棵草同时摇摆也是免费的。这是植被动画的标准做法，比骨骼便宜几个数量级。

Three.js 实现

// glTF 模型自带 morph targets，加载即用
const mesh = gltf.scene.getObjectByName('face');

// 看有哪些 target
console.log(mesh.morphTargetDictionary);
// { smile: 0, blink: 1, browUp: 2, ... }

// 设权重
mesh.morphTargetInfluences[0] = 0.7;  // 70% 微笑

// 动画：配合 GSAP 或 AnimationMixer
// AnimationMixer 可以播放模型内嵌的 morph 动画轨道

Godot 实现

# Godot 4：MeshInstance3D 的 blend_shape
var mesh_instance = $Character/Face

# 看有哪些 blend shape
for i in mesh_instance.get_blend_shape_count():
    print(mesh_instance.get_blend_shape_name(i))

# 设权重（-1.0 ~ 1.0）
mesh_instance.set("blend_shapes/Smile", 0.7)

口头描述练习

🗣️ RPG 对话系统的表情方案怎么描述？

"角色面部用 morph target 系统：美术做 30 个基础 target——6 个情绪（喜怒哀惊厌平）、8 个 viseme 口型、眼部细节（眨眼、眯眼、瞳孔方向）。对话时口型由音频分析驱动：实时提取音量包络映射到张口 target，元音识别映射到对应 viseme。情绪由对话配置表驱动，句子级切换，crossfade 0.3 秒过渡。眨眼用随机计时器（2~6 秒），说话时频率加倍。身体还是骨骼动画，手势和情绪联动——生气的句子自动触发握拳动画。"

→ 你用了 target 分类、音频驱动口型、情绪状态机、crossfade、随机眨眼、骨骼+morph 分工。这就是完整的对话表情方案。
